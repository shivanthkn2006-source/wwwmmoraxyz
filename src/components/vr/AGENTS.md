# VR World rules

- VR world distant/heavy areas (mountains, highway, cycling trail, heritage train) mount via ProximityGate (camera-distance with hysteresis, smaller radius on low-memory phones) and city systems are lazy chunks, because loading the whole world at once froze basic phones.
- VR World on-screen panels are wrapped in <VRFeature id> and hidden while VRTopDock is mounted (body[data-vr-clean]); the dock's icon strip reveals them, and a revealed feature floats above the base controls with its own saved drag grip, because the always-on HUD made VR unusable on phones and opened panels landed under the main pad.
- The Real Map always mounts the shared PlayerController (the avatar controller exists only inside M'Mora World), because without it sticks, buttons and arrow keys moved nothing.
- VR World buttons and physical game controllers go through src/lib/vrInput.ts, which reuses the world's existing key/event wiring, because a second movement system would drift out of sync.
- Heavy VR models (>5 MB) are never preloaded at import time and load only when used (e.g. the detailed bike only while riding, never on ≤4GB phones) behind an error boundary with a procedural fallback, because a 57 MB preload stalled and crashed VR World start.
- Repeated VR scenery (rails, sleepers, gravel) uses instanced meshes and moving fleets (metro trains) use distance LOD, because thousands of separate meshes exhausted phone memory.
- While VR World is active (src/lib/vrSession.ts), AfterAuthIdle hosts marked pauseInVR unmount, because background helpers outside the world compete with the 3D scene on phones.
- VR relic quests and the item bag live in src/lib/vrQuests.ts (vr_bag_items, vr_quest_progress; own-row RLS), and quest completion alerts go through notifySelf as vr_quest_complete, because one store keeps the world, bag panel and bell in sync.
- VR World spawns on the Real Map (src/worlds/realmap, OpenStreetMap chunks keyed in lat/lng, cached in IndexedDB) and the existing city is "M'Mora World" behind a doorway; src/worlds/worldMode.ts mounts only one world at a time, because both worlds together would exceed phone memory.
- Real Map blocks load device cache → shared osm-tile cache → small Overpass batches from the member's phone (own 3×3 blocks first, then ≤6, auto-retry with backoff; map servers block cloud IPs and reject big areas), and showing a member to others on the Real Map must check src/lib/vrPrivacy.ts first, because members can hide themselves.
- Members meeting, name tags and in-world chat live in src/worlds/meet (one presence+broadcast room per world / ~2 km Real Map area, pose sent ≤1/s, Real Map poses as lat/lng); the old 100 ms useMultiplayerPresence is off, because per-frame presence overloaded phones and left members invisible to each other.
- Walking goes through src/lib/vrWalk.ts (arrows/stick turn the camera then walk at human speed; stamina gates running), and the Use button goes through src/lib/vrUse.ts (nearest registered target wins), because separate handlers fired conflicting actions.
- Street relics are seeded from each block's real road points + the date (src/worlds/realmap/streetRelics.ts), so every member sees the same relics without a server table.
- Real Map street traffic (src/worlds/realmap/StreetTraffic.tsx) is one instanced mesh per kind (cars, bikes, people) on lanes built from the loaded OSM roads in src/worlds/realmap/mapIndex.ts, and its counts and render resolution follow src/worlds/realmap/thermalGovernor.ts, because separate meshes overheated phones.
- VR voice chat is peer-to-peer WebRTC between voice-on members in the same meet room, with signalling on the meet channel (src/worlds/meet/vrVoice.ts) and the mic opened only by the mic button, because a media server is not available.
- Portal invites go only through the notify-user function as type vr_invite (friends only, wording fixed on the server), because members cannot write alerts for each other.
- VR World search (src/worlds/search) only searches VR World sources (meet room, friends, mapIndex, relics, M'Mora landmarks) plus "Cities and places" from OpenStreetMap place search run on the member's phone (debounced, cached) that moves the Real Map origin via travelTo, because results from the rest of the platform would mislead inside the world.
- Real Map buildings/roads are drawn by src/worlds/realmap/streetLook.ts (merged walls with one shared window texture, roofs, road edge/centre lines) and names by MapLabels.tsx (nearest few only, count set by the thermal governor), because per-building meshes or labels would overload phones.
- Real Map places (shops, brands, malls, fuel, food, hotels, offices) come from the same per-block map request (CHUNK_V bumps refresh old saved blocks) and are shown only through MapLabels, because one label per place per block overloaded phones.
- "Follow my GPS" (src/worlds/realmap/gpsFollow.ts) is off by default, moves the avatar at most every few seconds and pauses above driving speed, because moving with every GPS fix is jittery and unsafe while driving.
- South India city blocks are pre-filled from the admin's own device (src/worlds/realmap/prefillCities.ts), because map servers block cloud servers.
- VR third-person view and crouch live in src/lib/vrView.ts (L button / V key, Crouch / C); the avatar is a procedural jointed figure drawn ahead of the camera (no model download), because heavy models crash basic phones.
- M'Mora World story items (keys, notes, locked doors) live in src/lib/vrStory.ts (device-saved, pure doorAction), night mode in src/components/vr/NightMode.tsx (local clock), and the admin's VR session auto-prepares South India city blocks via AdminAutoPrefill with a per-request chunk key, because a global key function would mix the background cities into the live street.
- VR World progress (world, map place, position, facing) is saved by VRSaveGameTicker into src/lib/vrSaveGame.ts only after start-up placement settles (isStartSettled), and resolveOrigin waits up to 3 s for the newer account save before resuming, because a default spawn must never overwrite the real save and members must resume on any device.
- Admin Real Map controls (demo bot, shop relic drops) live in vr_world_settings room 'realmap' via src/worlds/realmap/realmapAdminSettings.ts (admin writes, members read) and are applied by AdminRealmapSync, because per-device switches never reached other members.
- Green herbs and antique coins live in src/lib/vrPickups.ts (device + vr_save_games own-row account copy that also stores the latest game save; coins earn karma via earn_activity_karma 'vr_coin'), placed by src/worlds/mmora/PickupHouses.tsx through the shared Use button, and shown on the rotating VRMiniMap, because one store keeps the map, bag, stamina and Zoe in sync.
- Real Map enterable homes (src/worlds/realmap/StreetHouses.tsx, chosen per block by hash so every member sees the same doors) open the shared room overlay src/components/vr/VRRoomInterior.tsx via src/lib/vrInterior.ts, and water/parks/bridges come from the same per-block map request (OsmChunk.areas/waterways, road br flag) drawn by waterLook.ts, because a second map request or per-building room scenes would overload phones.
- Walls and buildings block walking through src/lib/vrSolids.ts (Real Map footprints from loaded blocks, closed M'Mora houses), called once in PlayerController's move step, and pickup sounds are synthesized in src/lib/vrSfx.ts, because a second movement path would drift and downloaded game sounds can't be shipped.
- M'Mora World (mode 'mmora', behind every Real Map portal) mounts only the new houses world (PickupHouses, ArchiveHouse, MMoraSigns, SavePoint, MMoraGround, return portal) with the shared PlayerController; the old VR Omega city (VRFeatureIntegration, crowd, cyber city, memory palace pieces) is not mounted anywhere, because the owner keeps it disconnected until it is rebuilt.
- Every person in VR World (you, members, demo explorer, street walkers) uses the one look in src/lib/vrHumanLook.ts (merged vertex-coloured mesh: hair, blue top, yellow trim, white trousers), because separate figures drifted into mismatched cylinders.
- Street traffic joins roads whose ends meet (buildLaneLinks in StreetTraffic.tsx) and only turns round at real dead ends, so cars and people travel road to road.
- VR lights (building windows, street lamps) switch through src/lib/vrLights.ts schedules (one 30 s ticker over registered materials) and lamps are instanced (src/worlds/StreetLamps.tsx), because per-lamp lights or per-frame checks overheat phones.
- Each city gets its own M'Mora World: the meet room and saved benches are keyed by mmoraCityKey() (src/worlds/worldMode.ts), so a Chennai portal opens Chennai's world.
- M'Mora World bench economy lives in src/worlds/mmora/MMoraBenches.tsx (sit earns coins, coins build benches via the shared Use button, built benches saved per city on the device).
- The VR item bag (src/components/vr/VRBagPanel.tsx) is one attaché-case grid portalled to the page body (herbs 1×2, coins/relics 1×1, tap-to-move layout and extra rows saved on the device), because panels inside the HUD sat under other controls.
- M'Mora coins share one look from src/lib/vrCoinLook.ts (gold 50 / blue 10 / yellow 1 faces, coin bag at 100+), and the member's VR name and female look come from src/lib/vrSelf.ts (profile gender) and travel to others as the pose `f` flag, because separate coin art or per-screen profile reads would drift apart.
- M'Mora Village's outdoor look (snow ground, bare trees, stone walls, church, animals, crows) lives in src/worlds/mmora/VillageLook.tsx as instanced vertex-coloured meshes, because one draw call per kind keeps the village light on phones.
- M'Mora Village animals (src/worlds/mmora/VillageAnimals.tsx) mount per herd only within ~70 m of the player and move/call only within ~35 m, with voices synthesized in src/lib/vrAnimalSfx.ts, because always-on animals and downloaded sounds would load phones at portal entry.
- M'Mora Village sky and weather live in src/worlds/mmora/VillageSky.tsx (local clock night, lunar-cycle moon phase, one shared Open-Meteo reading taken at the member's real device location first and the map place only as fallback, rain whenever precipitation is reported, thunder from 95–99 codes in the current/adjacent hours, synthesized thunder/rain resumed on first tap), because the map place can be a portal city far from where the member really is.
- M'Mora Village house rooms (furniture, fireplace, side table) mount only within ~16 m of that house, and every other village light is a <PooledLight> served by src/worlds/LightPool.tsx (fixed handful of real point lights moved to the nearest spots), because twenty separate point lights, and rooms adding/removing lights (which recompiles every material), made the village hang while walking. Player level, found gear and equipped gear sync to vr_player_progress (own-row RLS) via src/lib/vrGear.ts so progress follows the member across devices.
- M'Mora Village multiplayer is capped at 5 members per room by src/worlds/meet/villageParty.ts (earliest join, then id; extras move to the next room copy '#N'), applied in vrMeet's presence sync, because a server-free shared rank keeps every phone agreeing who is in. Hidden members are untracked and never take a place (a hidden viewer doesn't count itself); moveVillageGroup lets members switch copies, a full copy passes them on.
- Village guns use magazines and reserves from src/lib/vrAmmo.ts (fire/reload in VillageVillagers' Use action, condition + rounds under the health bar), because one ammo store keeps the HUD and combat in agreement.

- M'Mora Village's street plan (houses, square, lanes, church/beach/castle roads, roadside prop placement, villager routes, landmark positions) lives in src/worlds/mmora/villageMap.ts and src/test/villageRoads.test.ts fails if anything stands on a road, because props and houses had drifted into the lanes and blocked the castle road.- The account game save (vr_save_games) keeps the newest save/pickups by their 'at' timestamp via a BEFORE UPDATE trigger, and the device only bumps 'at' when the member moves or turns, because idle tabs/devices on one account otherwise overwrote the real last-played spot.
- Village third-person uses src/lib/vrChaseCam.ts: the avatar body is the player and the camera stays exactly AVATAR_AHEAD behind it, because other systems locate the avatar as camera + forward × AVATAR_AHEAD.
- Skirt-avatar guns (pickHeldWeapon) are held via vrWeaponGrip: hold frame from the live shoulder joint + Three CCD arms + rig-measured wrist/finger axes, because fixed avatar-space offsets clipped the stock and fixed Euler wrists/curls bent hands sideways.
